What do these words mean?
Average response time
The usual time one request takes from start to finish.
Slowest 5% (p95)
95 out of 100 requests finish at least this fast. It shows how bad the slow ones get, which the average hides. It is estimated from timing buckets, so it is approximate.
Error rate
Share of requests that failed because of a server problem (HTTP 5xx). Rejected requests, such as a missing API key or too many requests (4xx), are counted separately.
Chunks indexed
Pieces of your documents stored for searching. More chunks means a bigger knowledge base.
Cache hit rate
How often a repeated question reused an earlier computation instead of running the embedding model again. Higher is faster and cheaper.
Self-healing outcomes
Passed first time: the answer was verified immediately. Recovered: it failed a check, was repaired and then passed. Declined: it could not be verified after retrying, so the service said so instead of guessing.

Counts are totals since the server last started. Traces and cost data from OpenTelemetry or Langfuse, when enabled, are sent to that tool and do not appear here.
